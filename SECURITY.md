# Security Policy

ASTERA is currently a contest prototype that uses synthetic browser data. It is not yet intended to store real household, identity, payment, or security-system information.

## Reporting a vulnerability

Do not open a public issue containing sensitive details. Contact the repository owner privately through GitHub and include the affected version, reproduction steps, impact, and any safe proof of concept. Please avoid accessing real user data or disrupting services while investigating.

## Production security expectations

Before handling real estate operations, the project must add server-enforced authorization, MFA, secure evidence storage, secret management, encryption, retention controls, tamper-evident auditing, dependency scanning, monitoring, backup and restore procedures, and an incident response owner.

Security claims in product copy must always match tested, deployed capability.
